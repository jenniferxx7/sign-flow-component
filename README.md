# 簽核流程設定元件

設定表單簽核關卡的網頁元件，有三個畫面：

- **設定畫面**：從 8 種簽核來源加入關卡，並設定每一關的簽核方式、期限和權限。8 種來源是指定員工、員工群組、部門成員、部門主管、組織層級、簽核角色、表單關係人、條件式。
- **流程總覽**：按「儲存流程」後顯示。分成「簽核流程設定」（每一關由誰簽核）和「簽核狀態」（未簽核／簽核中／簽核完成三種情境）兩個區塊。
- **完整簽核畫面**：單張表單的簽核進度。

純 HTML / CSS / JavaScript，不需要安裝或建置工具。

## 檔案結構

```
index.html            頁面入口
css/style.css         樣式
js/data-source.js     資料層：讀取組織資料、儲存流程（之後接 API 只改這裡）
js/org-model.js       把組織資料轉成 8 種簽核來源，並算出動態簽核人
js/app.js             畫面與互動
data/org.js           組織資料（目前是範例資料）
spec.html             功能規格文件：左側為介面（含標號），右側為規格表
css/spec.css          規格文件樣式
js/spec-page.js       規格內容（項次、說明、標號位置）
js/spec-markers.js    介面上的標號，只在 spec.html 內嵌時（index.html?spec=1）作用
```

修改介面後，記得同步更新 `js/spec-page.js` 裡對應項次的說明、`sel`（標號位置）和 `go`（點項次時自動切換到哪個畫面，步驟定義在同檔的 `GO`）。

`data/org.json` 已停用，可以直接刪除。

## 在本機開啟

直接用瀏覽器開啟 `index.html` 即可，不需要架伺服器。

## 放上 GitHub 並分享網址

1. 在 GitHub 建立一個 **私人（Private）** repo。
2. 上傳這個資料夾裡的所有檔案。可以用 GitHub 網頁版拖曳上傳，也可以用 GitHub Desktop 或 git 指令。
3. 發布成網站，**依資料是否敏感選擇方式**：
   - **組織資料是真實員工資料**：不要用一般的 GitHub Pages，因為它是公開網站，任何人都看得到。請改用以下任一種：
     - GitHub Enterprise Cloud 的私人 Pages：限定組織成員可以看。
     - 公司內網的靜態網站主機：把整個資料夾放上去即可。
   - **只放範例或去識別化資料**：可以用 GitHub Pages。到 repo 的 Settings → Pages，Source 選 `main` 分支的根目錄，存檔後會得到一個網址。

## 更新組織資料

修改 `data/org.js` 就好。檔案開頭是 `window.ORG_DATA = `，後面接一段 JSON。

| 區塊 | 欄位 | 說明 |
|---|---|---|
| `grades` | 字串陣列 | 職級，由低到高排列，用於「申請人職等 以上（含）／以下（含）」條件 |
| `departments` | `id`、`name`、`parentId`、`level`、`managerId`、`deputyIds`（選填） | 組織樹。`parentId` 為上層部門，最上層填 `null`；`level` 例如「部」「處」「中心」「公司」，「逐級簽核至○級」的選項由這裡產生；`managerId` 為部門主管的員編；`deputyIds` 為副主管員編（可多位） |
| `employees` | `id`、`name`、`deptId`、`title`、`grade`、`deputyId`（選填）、`status`（選填） | 員工。`deputyId` 為職務代理人的員編；`status` 為在職狀態：`在職`（預設）、`離職`、`留職停薪` |
| `groups` | `id`、`name`、`memberIds` | 員工群組 |
| `roles` | `id`、`name`、`deptId`（選填）、`memberIds` | 簽核角色，例如財務審核、法務審核 |
| `form.name` | 字串 | 表單名稱 |
| `form.fields` | `key`、`label`、`type`、`options`、`unit` | 可用於條件式的表單欄位。`type` 可為 `num`（數字）、`enum`（選項）、`rank`（職級）、`dept`（部門）、`text`（文字）、`person`（人員，作為表單關係人） |
| `form.presetConditions` | `id`、`name`、`logic`、`clauses`、`then`、`otherwise` | 預設條件。`then` 是符合時的簽核人，格式為「來源:項目」，例如 `org:1`、`head:dept:FIN`、`role:fin` |
| `sample` | `applicantId`、`submittedAt`、`values` | 預覽用的範例申請單，用來示範「依申請人動態帶入」和簽核進度畫面 |

部門主管、直屬主管、逐級主管會依 `departments` 的上下層關係和 `managerId` 自動算出，不需要另外填。

預設條件用到的欄位必須在 `form.fields` 裡。用到表單沒有的欄位，或找不到簽核人時，這條預設條件會被略過，不會出現在畫面上，並在瀏覽器主控台留下警告。

## 畫面示意（狀態預覽）

頁面右下角的「畫面示意」選單可以切換以下狀態，也可以直接在網址後面加參數：

| 狀態 | 網址參數 | 說明 |
|---|---|---|
| 正常畫面 | （不加） | |
| 載入中 | `?demo=loading` | 停在載入組織資料的畫面 |
| 載入失敗 | `?demo=load-error` | 顯示錯誤訊息與「重新載入」按鈕 |
| 儲存失敗 | `?demo=save-error` | 加入關卡後按「儲存流程」，會顯示失敗訊息與「重新儲存」 |

選單最下方的「查看功能規格」會開啟 `spec.html`（在規格頁內嵌時自動隱藏）。

正式上線前，可以把 `index.html` 裡的 `demo-menu` 區塊移除。

## 改成即時串接 HR 系統

頁面只透過 `js/data-source.js` 取得資料。要接 API 時：

1. 改寫 `loadOrg()`，改成向 API 取得資料，並回傳與 `data/org.js` 相同的格式。例如：
   ```js
   async function loadOrg() {
     const res = await fetch('/api/org');
     if (!res.ok) throw new Error('無法讀取組織資料');
     return res.json();
   }
   ```
2. 改寫 `saveFlow(flow)`，改成呼叫儲存流程的 API。目前只會在瀏覽器主控台輸出內容。
3. 移除 `index.html` 裡的 `<script src="data/org.js"></script>`。

員工人數很多時，建議 API 支援依關鍵字搜尋，並把搜尋改成由伺服器處理。目前畫面一次最多列出 100 筆。

## 操作說明

- 員工群組、簽核角色：在左側切到「員工群組」或「簽核角色」，可以「新增群組／角色」，或按每一列的筆型圖示編輯名稱、所屬部門（角色）和成員；關卡詳細面板裡也有「編輯群組／角色」。刪除前會先確認，若流程有用到，該關卡會一併移除。名單透過 `DataSource.saveDirectory()` 儲存，目前只在主控台輸出，重新整理後會回到 `data/org.js` 的內容。
- 簽核對象與例外處理（關卡詳細面板）：
  - 部門主管、組織層級可勾選「主管」「副主管」，兩者都勾時同一層依副主管 → 主管簽核。
  - 每一關可設定「簽核人不在職時」「找不到簽核人時」的處理方式，以及重複簽核人、申請人本人是否自動略過。
  - 實際簽核人由 `js/org-model.js` 的 `resolve()` 計算，完整規則寫在 `spec.html` 第十節。
  - 範例資料刻意放入例外情境：營運中心主管與營運處副主管留職停薪、楊詩涵與蔡宗翰離職、總經理室特助找不到第 2、3 層主管。
- 關卡順序：用「上移」「下移」按鈕，或直接拖曳關卡卡片調整。
- 移除單一關卡、清除全部、刪除自訂條件時，都會先跳出確認對話框。
- 流程版本：第一次儲存為第 1 版。之後修改並儲存，會另存為新版本；若有表單正在簽核，儲存前會跳出確認，沒有則直接儲存。
  - **已在簽核中的表單**沿用送出當時的版本完成簽核。
  - **儲存之後新送出的表單**才套用新版本。
  - 簽核中的張數取自 `data/org.js` 的 `sample.inProgressCount`，目前是範例數字。
  - 總覽頁的「簽核流程設定」會標示目前生效的版本。有兩個以上版本時，可以切換查看舊版本的流程內容（唯讀），並顯示每版的儲存時間。版本紀錄目前只存在頁面中，重新整理就會清空。

## 目前的限制

- 「儲存流程」尚未接後端，重新整理頁面後設定會清空。
- 「依申請人動態帶入」的人員和簽核進度畫面，都以 `sample` 指定的範例申請人示範。
- 簽核進度畫面的核准時間是範例時間。
